# Session and playback recovery after the MiniPC upgrade

Authority: fix the reported successful-login/playback/logout loop and retain the requested saved credentials. Read the `Navidrome Maintenance` chat as context. Standing authorization includes final release and local delivery, with hidden testing and preserved settings/queue. Do not start Docker on Windows.

The November 7 replacement standing instructions were reread during execution, along with the relevant installed specification/debugging guidance. Their bounded same-component reliability repair and deployment authority applies to the evidenced ingress defect; no new feature or independent workstream is opened.

## Requirements

- R1: A resource failure after successful native token renewal must remain a resource failure. A 404, cancellation, rate limit, server error or network failure must not erase a saved password or its preference, or sign out an otherwise valid session.
- R2: Native renewal must be serialized per server using the actual in-flight promise. Requests using superseded credentials reuse the latest token; unrelated servers and a newly selected session must remain untouched. Explicit logout/forget remains intentional credential removal.
- R3: Restore cached-song lookup, artwork and real audio access through the existing music hostname after the server ID migration. Preserve both historical and current IDs, authenticated access, histories, queues and existing services. Verify the actual public route rather than only the internal compatibility proxy. No database or cache resets.
- R4: Verify affected transports and fork regressions, production build/package, normal nine-asset Windows release and independent delivered payload; install locally and verify login persistence, paused startup and playback using hidden diagnostics. Preserve user profile and active unrelated processes. Clean expendable task output.

## Root-cause evidence

Readback of `Navidrome Maintenance` confirms maintenance 2026.11.06.1, Navidrome 0.64.2 and the TuneLog ID adapter. Actual server probes prove fresh native login, native JWT and Subsonic token authentication succeed. The old cached song `MNXIVE5Dtkt2dYMkI48UF0` returns 404 directly on port 4533 and 200 through the adapter on 4534. Public `music.remaxku.eu` traffic is logged by the native server without the adapter. At 22:37 and 22:39 UTC on November 6, the installed client logs successful user authentication, obsolete-song lookup failures, password removal and loss of selected server. Native logs show repeated renewal requests followed by 404 and eventually 429. Persisted authentication records independently show savePassword true becoming false and credential fields being cleared.

The native response interceptor catches errors from replaying the original resource request inside its authentication catch; it therefore schedules authenticationFailure on a post-renewal 404. That helper removes the encrypted password and invokes destructive logout. Requests also capture tokens before waiting for unrelated renewal and use timer-based global synchronization. The startup hook independently removes saved passwords after non-network failures.
