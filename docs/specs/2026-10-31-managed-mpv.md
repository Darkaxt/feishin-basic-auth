# Automatic Windows MPV provisioning

Authority: user approved first-launch GitHub download of a pinned, verified MPV with a custom executable override, then asked why existing playback regressed. Implementation, normal release and local delivery are already authorized. No Docker and no visible runtime launch or desktop interaction.

## Required behavior

- R1: Windows x64 and ARM64 desktop playback automatically obtain an architecture-matched MPV from a pinned GitHub release when no explicit executable is configured. No package manager, PATH entry, administrator permission, external archive tool or user download is required. Non-Windows discovery is preserved.
- R2: An explicit executable is authoritative and never overwritten. An unset override uses the application-managed runtime consistently, independent of launcher PATH. Removing an override returns to automatic management.
- R3: Verify the pinned archive SHA256 before extraction/execution, verify the executable SHA256 and PE architecture, extract only required runtime files, and atomically publish a completed runtime. Reuse the verified cached runtime offline. Concurrent requests share the same acquisition. Incomplete or failed downloads must not become runnable installations; no arbitrary retries or lifecycle deadlines.
- R4: Integrate acquisition into real MPV initialization and audio-device enumeration. Report download/verification failures with their actual Error details and an actionable message. Preserve queue recovery, seeking, paused startup/no autoplay, proxy BasicAuth, LidaClips, fullscreen and updater/profile identity. Keep existing web fallback available after acquisition failure.
- R5: Explain the observed regression from evidence and protect clean-PATH startup. The same ba26 binary launched SVP MPV on October 25; the first logged discovery failure is October 26. Resolver unchanged since August 29; no configured mpv_path exists, and the failing process PATH omits mpv64. The agent environment still discovers both SVP MPV and Scoop MPV, confirming a launcher-environment difference. This does not establish a machine-wide PATH edit or identify who changed any environment. Prior delivery verification inherited the agent environment and missed the ordinary-launch dependency.
- R6: Deliver a normal verified ba27 GitHub release with all established Windows assets, independently verify the downloaded package, deploy locally preserving profile and queue, and verify hidden startup uses managed MPV. Check a real engine workflow without audible playback or desktop takeover. Clean expendable generated output after its last consumer.

## Decisions and boundaries

Windows-only automatic provisioning matches this fork's existing Windows release channel. Use the native Windows tar executable for checksum-verified 7z extraction; it has been exercised against both chosen x64 and ARM64 archives. No new archive dependency or generalized downloader service. The source is shinchiro/mpv-winbuild-cmake, linked by mpv.io's Windows installation page. Pin 20261021 / MPV e471496c56; verify published digests against independently retrieved bytes. Include source/provenance links in documentation; download the upstream distribution directly without republishing its binaries.

Small disposable orchestration and receipts: E:/Temp/feishin-ba27. Native extraction, build/test scratch and packaging inspection: D:/Temp/feishin-ba27 because they need sustained/small-file I/O. Existing checkout-bound out/dist paths remain unchanged and are registered for cleanup. Runtime storage on this host must be configured under D:/Tools/Feishin separately from disposable scratch; preserve its continuing installed-app consumer. Default product storage remains profile-private on other installations.
